# Documentation site — authoring guide

The site is built by `build.py`, a **standard-library-only** generator. No
MkDocs, no plugins, no network: the same interpreter that runs the tests builds
the pages, which is why CI can publish them on any runner.

```bash
python docs/site/build.py                 # -> public/
python docs/site/build.py --serve 8000    # build + preview at localhost:8000
python docs/site/build.py --check         # build, verify links, delete output
```

`--check` is what CI runs. The build fails on:

- a page in `nav.toml` that does not exist,
- a `.md` file under `pages/` that is not in `nav.toml` (an orphan),
- a broken internal link or `#anchor`,
- a missing image or asset.

## Layout

```text
docs/site/
├── nav.toml                 sections, page order, titles, search blurbs
├── pages/                   one .md per page (subfolders are fine)
│   ├── index.md
│   ├── start/ install/ prepare/ run/ gui/ config/ results/ extend/ reference/
├── assets/
│   ├── css/site.css         the whole design system (light + dark)
│   ├── js/site.js           theme, search, tabs, copy buttons, scrollspy
│   ├── img/favicon.svg
│   ├── diagrams/*.svg       generated by tools/make_diagrams.py
│   └── screenshots/*.png    generated by tools/make_screenshots.py
└── tools/
    ├── make_diagrams.py     SVG figures (no Graphviz)
    ├── make_screenshots.py  real GUI screenshots (needs a display)
    └── make_demo_project.py neutral example project from data/ernie
```

## Adding a page

1. Create `pages/<section>/<name>.md`; start with a single `# Title`.
2. Add a row to `nav.toml`:

   ```toml
   [[sections]]
   title = "Reference"
   pages = [
     ["My page", "reference/my-page.md", "One line for search and the meta description."],
   ]
   ```

3. Link to it from at least one other page (the build does not require it, but
   an unlinked page is a page nobody reads).
4. Run `build.py --check`.

## The Markdown subset

Everything else is escaped, not passed through.

| Syntax | Renders as |
|---|---|
| `#` … `####` | headings with anchors and a right-hand TOC |
| paragraphs, `-` / `1.` lists, `- [x]` tasks | lists (one nesting level) |
| GFM pipe tables | scrollable table with a header |
| fenced code with a language tag | code block with a language label and **Copy** |
| `> quote` | blockquote |
| `**bold**`, `*italic*`, `` `code` ``, `[text](url)`, `![alt](img)` | inline |
| `---` | horizontal rule |
| `!!! note "Title"` + 4-space body | admonition (`note`, `tip`, `warning`, `danger`, `example`) |
| `=== "Tab"` + 4-space body | tab set (consecutive `===` lines form one set) |
| a raw HTML block | passed through (used for `<figure>` wrappers) |

Links to other pages use the `.md` extension and are rewritten to `.html`
relative to the current page. `assets/...` references are prefixed with the
page's root, **including inside raw HTML figures**.

## Writing conventions

- A researcher writing to colleagues: second person for procedures, first
  plural for design decisions. No marketing adjectives.
- Every GUI page names the tab exactly as it is labelled.
- Settings are tables with **key / meaning / scope / default / restart**.
- Commands are copyable `bash` blocks; show the expected output when a command
  can fail silently.
- Separate measured facts from modeled or simulated values. State units,
  coordinate frames and sample counts. Cite the method paper for a scientific
  claim.
- State limitations next to the feature they affect. R² is not a significance
  test, the virtual EMG is a model, and the simulation is not a substitute for
  a measurement.
- Safety uses one reserved style: `!!! danger "Safety: …"`.
- Prefer commas, colons, semicolons or parentheses over em dashes in new
  prose. Keep quoted UI strings and log messages verbatim.
- End a page with a `## Next` section pointing at one or two pages.
- Do not duplicate `docs/CONFIG.md` or `docs/ROBOTS.md`; link them.

## Figures

Diagrams are generated, not hand-drawn in a GUI:

```bash
python docs/site/tools/make_diagrams.py
```

Each figure is a function in `tools/make_diagrams.py` returning SVG; the helper
functions (`box`, `arrow`, `text`, `note`) keep the palette consistent. For PNG
copies next to the SVGs, run `python docs/site/tools/make_diagram_pngs.py` with
an environment that has PyQt5.

Screenshots are real windows:

```bash
# needs a display and data/ernie
python docs/site/tools/make_screenshots.py
```

The script starts the simulated relay/nav/robot (or reuses a stack on port
5000), builds the real `MainWindow`, loads a neutral example project and drives
the pages to representative states. The 3-D view is rendered by
`MeshWidget.screenshot()` and composited into the window image (Qt cannot grab
the VTK surface), and the robot view is composited from an offscreen MuJoCo
render for the same reason.

Do not hand-edit a generated SVG or PNG; change the generator and rerun it.

## CI

`.gitlab-ci.yml`:

| Job | What it does |
|---|---|
| `check:docs` | `build.py --check` on MRs and branches |
| `pages` (GitHub Actions) | builds `_site/`: on `dev` to the repo's `gh-pages` (development docs), on `main` to `TMS-NeuroPilot/tms-neuropilot.github.io` (release docs) |

Two sites are published by the `.github/workflows/pages.yml` workflow:

| Branch | Site | Mechanism |
|---|---|---|
| `main` | <https://tms-neuropilot.github.io/> | `_site/` force-pushed to the organisation's root Pages repository (`TMS-NeuroPilot/tms-neuropilot.github.io` — generated, never edit it) |
| `dev` | <https://tms-neuropilot.github.io/tms-neuropilot/> | `_site/` force-pushed to this repository's `gh-pages` branch, built with `--noindex` so it does not compete with the release site |

The `check:docs` job pins `python:3.11-alpine`
because the shared runners' default image has no Python or bash; it does not
need the lab environment.

The `tests/test_docs_site.py` suite additionally verifies that every
environment key, lab-profile key, relay topic and fit function is documented.
A new key without a docs row fails CI.
